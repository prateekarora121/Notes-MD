# Changelog Summaries (context of how the guide was built)
The guide was consolidated over seven passes, each closing gaps for a 2026 senior/lead .NET-on-AWS bar:
- **[new content]** (pass 1): ECS/EKS/Fargate/Lambda for .NET, Beanstalk vs ECS vs Lambda, S3 storage classes/lifecycle, EBS/EFS/S3, VPC reference diagram, RDS Multi-AZ vs Read Replicas vs Aurora, EventBridge, event-driven reference flow, Secrets Manager vs Parameter Store, least privilege/boundaries, CloudWatch vs X-Ray, cost optimization, Well-Architected 6 pillars, DR strategies.
- **[gaps]** (pass 2): EC2 sizing/pricing/CPU-credit gotcha, S3 lifecycle patterns + Terraform, Fargate/ECS/EKS trade-offs (honest framing), Multi-AZ vs Read Replica drill, VPC rapid-fire, Well-Architected rapid recall, CloudFormation vs Terraform/CDKTF.
- **[iam-core]** (pass 3): IAM fundamentals restructured — overview (global/free/eventual consistency), root + root-only actions, shared responsibility, users/groups, policy types, full policy fields + `bucket` vs `bucket/*`, password policy, MFA (console vs CLI), access keys + credential chain, security tools, hands-on walkthroughs, rapid-fire; role sub-topics (instance profile, IMDSv1/v2, `iam:PassRole`, STS table, role chaining, service-linked roles, task vs execution role, IRSA, Identity Center).
- **[services-core]** (pass 4): full EC2/instance-storage/S3/S3-security, scalability & load balancing, databases/analytics/caching, streaming (Kinesis/MQ), networking (Flow Logs/Peering/TGW/Endpoints/hybrid), Route 53, global edge (CloudFront/GA/Local Zones), containers (Docker/ECS/ECR), observability (CloudTrail/Health/Container Insights), security services, management/org/billing.
- **[resume-aligned]** (pass 5): restructure into four tiers (Part I claimed core → IV reference), Priority Map + Azure→AWS translation + Resume Deep-Dives + 60-sec answer, Terraform/CDKTF in practice, SQS/SNS operational detail, Step Functions, Systems Manager, Migration & Data Transfer, Lambda versions/aliases/layers/destinations, DAX, Support plans, Free Tier/pricing, resilience testing.
- **[net-fundamentals]** (pass 6): CIDR/subnetting ground-up (32-bit view, `/n` math, mask octets, **AWS's 5 reserved IPs**, block-size trick, longest prefix match, RFC 1918) + the overlapping-CIDR failure walkthrough (peering won't create, TGW blackholes silently, **the `local`-route killer**, partial overlap, PrivateLink as the fix, allocation registry, IPAM).
- **[topology]** (pass 7): the only pass driven by a **real production stack** rather than the syllabus — a Windows container on ECS-on-EC2 behind an internal ALB in a VPC the app doesn't own. **Client VPN** (four objects, the two-gate authorization-rule-vs-SG distinction, split-tunnel as a NAT-cost decision, immutable client CIDR, hourly-floor pricing) · **inherited network / shared VPC** (three operating models, RAM *subnet* sharing, cross-account SG referencing, free same-AZ inter-account traffic, tags-as-contract, isolation accepted not achieved) · **internal vs internet-facing ALB** (immutable `scheme`, and ALB's ≥2 AZs / `/27` / 8-free-IPs subnet requirements) · **interface endpoint AZ placement** (one ENI per AZ, zonal DNS, provider-AZ matching, **AZ names differ per account, AZ IDs don't**) · **ECS dynamic host ports** (`32768–65535` SG rule vs the unrelated NACL ephemeral trap; `bridge` makes per-service SG isolation impossible).

**Contradictions flagged:** source had a large exact-duplicate of the Lambda deep-dive and a duplicated DynamoDB trick-questions block (merged, no factual conflict); no genuine contradictions. Corrections: resource-based vs AssumeRole cross-account distinction clarified; "S3 eventually consistent for overwrites" is out of date (strong since Dec 2020); per-partition DynamoDB throughput (~3,000 RCU/1,000 WCU) marked directional, not contractual.
