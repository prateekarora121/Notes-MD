# S3

---

## 1. Buckets, Access & Hosting

### Buckets & Objects

Infinitely scalable **object** storage (not filesystem), 11 nines durability, no capacity to provision.
- Name **globally unique**, 3–63 chars, lowercase/nums/hyphens/dots, no uppercase/underscores/IP-like.
- Bucket lives in one region (namespace global); not nested.
- **Key = full path** (flat; console fakes folders from prefixes + `/` delimiter). Max object **5 TB**; **single PUT ≤5 GB** → multipart mandatory above (recommended >100 MB). ≤10 tags, version ID if versioning on.
- **❗ Strong read-after-write consistency for PUT/overwrite/DELETE + consistent LIST since Dec 2020** — "S3 is eventually consistent for overwrites" is out of date.
`aws s3` (high-level cp/sync/mv) vs `aws s3api` (raw per-call).

### Bucket Policies & Access Control

IAM policy (identity) · **bucket policy** (resource, cross-account, needs `Principal`) · ACLs (**avoid** — set Object Ownership = "Bucket owner enforced") · Access Points (many teams).
Two memorizable guardrails (Deny):
```json
{ "Sid":"DenyUnEncryptedUploads","Effect":"Deny","Principal":"*","Action":"s3:PutObject",
  "Resource":"arn:aws:s3:::my-bucket/*",
  "Condition":{"StringNotEquals":{"s3:x-amz-server-side-encryption":"aws:kms"}} }
{ "Sid":"DenyInsecureTransport","Effect":"Deny","Principal":"*","Action":"s3:*",
  "Resource":["arn:aws:s3:::my-bucket","arn:aws:s3:::my-bucket/*"],
  "Condition":{"Bool":{"aws:SecureTransport":"false"}} }
```
**Block Public Access (BPA):** 4 toggles at account + bucket level, **on by default since 2023**. Account-level overrides bucket. "How to guarantee no public bucket org-wide?" = account BPA + SCP + Access Analyzer.

### Static Website Hosting

Enable + index/error docs. **❗ Website endpoint is HTTP only** → put **CloudFront + OAC** in front, keep bucket private (TLS via ACM, custom domain, caching). REST endpoint = HTTPS + IAM but no index behaviour; website endpoint = index/redirects but HTTP-only/public.

### Access Points & Object Lambda

Named endpoints, each with own DNS + policy (per-team, per-prefix) — keeps bucket policy simple; can be VPC-restricted; Multi-Region variant. **Object Lambda** = run a Lambda on the GET path (redact PII, resize, filter) without a second copy.

## 2. Storage Classes, Lifecycle & Versioning

### Versioning & Replication

Versioning: keeps every version; only **suspendable** not off; DELETE = **delete marker** (delete it to restore); permanent delete needs version ID; prereq for replication + MFA Delete. Pay per version → pair with lifecycle expiring **noncurrent** versions.
Replication CRR (DR/latency/residency) vs SRR (log aggregation/test seeding). Rules: versioning on both sides + IAM role; **async, not retroactive** (backfill = S3 Batch Replication); delete markers optionally replicated, **permanent deletes never**; **no chaining**; cross-account OK; **RTC** = 15-min SLA; **Multi-Region Access Points** = active-active S3.

### Storage Classes & Lifecycle

| Class | Use | Avail | Min duration | Retrieval |
|---|---|---|---|---|
| Standard | Frequent | 99.99% | None | Immediate |
| Intelligent-Tiering | Unknown patterns | 99.9% | None | Immediate (auto) |
| Standard-IA | Infrequent, ms | 99.9% | 30d | Immediate |
| One Zone-IA | Infrequent, recreatable | 99.5% | 30d | Immediate |
| Glacier Instant | Archive, ms | 99.9% | 90d | Immediate |
| Glacier Flexible | Archive, occasional | 99.99% | 90d | Min–hours |
| Glacier Deep Archive | Compliance | 99.99% | 180d | ~12h |

Gotchas: IA charges retrieval fee (only for genuinely infrequent); **min-duration billed even if deleted early**; Intelligent-Tiering has per-object monitoring fee (good default when unknown); versioned old versions need own rules; strongly consistent since Dec 2020.

**Lifecycle patterns:** logs = Standard→IA@30→Glacier@90→expire@365; backups = →Deep Archive@1–7d; unpredictable = Intelligent-Tiering; compliance = →Deep Archive, no expiry (or legal period); temp = expire@1–7d no transition. **Min-duration trap:** aggressive transitions on short-lived data can cost *more* than leaving on Standard.
```hcl
resource "aws_s3_bucket_lifecycle_configuration" "logs" {
  bucket = aws_s3_bucket.logs.id
  rule { id="logs-tiering"; status="Enabled"; filter { prefix="logs/" }
    transition { days=30; storage_class="STANDARD_IA" }
    transition { days=90; storage_class="GLACIER" }
    expiration { days=365 } }
  rule { id="expire-noncurrent"; status="Enabled"; filter {}
    noncurrent_version_expiration { noncurrent_days=90 } }   # the versioning fix
}
```

### Object Lock & Glacier Vault Lock

**Object Lock = WORM**, needs versioning + enabled at bucket creation. **Governance** (holders of `s3:BypassGovernanceRetention` can override) vs **Compliance** (nobody, not root — genuinely immutable). **Legal Hold** = on/off, no expiry. **Glacier Vault Lock** = same for vaults (SEC 17a-4). Object Lock Compliance = the one ransomware/insider control even root can't bypass.

## 3. Performance, Cost & Operations

### Performance, Analytics & Cost

**3,500 write / 5,500 read requests per second per prefix**, unlimited prefixes → spread keys across prefixes. Multipart (>5 GB required, add lifecycle to abort incomplete uploads — else billed forever, invisible); Transfer Acceleration (edge, long-distance); byte-range fetch; S3 Select (SQL over one object). Analytics: Storage Lens (org dashboards), Storage Class Analysis (recommend IA), S3 Inventory (report + Batch manifest), CloudWatch metrics, event notifications (Lambda/SQS/SNS/EventBridge — EventBridge richer).

### Batch Operations

One op over billions from a manifest (Inventory or CSV): copy, tag, ACL, restore Glacier, Object Lock, **invoke Lambda per object**. Answer to "fix 40M existing objects" — don't loop, run a Batch job.

### Requester Pays

Requester pays request+egress; owner pays storage. Requester must be authenticated + send `x-amz-request-payer: requester`. For distributing large shared datasets.

### Best Practices

Account BPA on + disable ACLs · enforce encryption+HTTPS via Deny policy · versioning + noncurrent expiration + abort incomplete multipart · lifecycle by measured pattern (Intelligent-Tiering if unknown) · spread prefixes + multipart · CloudFront+OAC over private bucket · access logging/CloudTrail data events · CRR what you can't lose (not a versioning substitute) · watch cost leaks (old versions, incomplete uploads, forgotten log buckets, cross-region).

## 4. Security & Compliance

### Shared Responsibility

AWS = infra + 11 nines durability + API + disk destruction + encryption options. You = **bucket/IAM policies + BPA + versioning/replication/lifecycle + choosing/enforcing encryption + retention (Object Lock/MFA Delete)**. "S3 never lost my data but will let me make it public — durability is AWS's, access/retention are mine." **S3 breaches = config failures, not durability.**

### Security: Encryption (4 types)

Defence in depth: BPA → bucket/IAM → encryption at rest+transit → versioning+Object Lock → logging → VPC endpoint.
| Type | Key | Audit | When |
|---|---|---|---|
| SSE-S3 | AWS AES-256 | None | **Default** (auto since Jan 2023), free |
| SSE-KMS | Your KMS key | ✅ CloudTrail per decrypt | Auditability/rotation; needs `s3:GetObject` **+ `kms:Decrypt`** |
| DSSE-KMS | KMS twice | ✅ | Dual-layer mandates |
| SSE-C | You (key in header, never stored) | Limited | Sole custody; HTTPS mandatory; lose key = lost data |
| Client-side | You, before upload | N/A | Zero-trust in provider |

**❗ SSE-KMS gotcha:** every GET/PUT = KMS `Decrypt`/`GenerateDataKey` call → per-region quota → `ThrottlingException` while S3 is fine. Fix = **S3 Bucket Keys** (~99% fewer KMS calls). In transit = enforce HTTPS via `aws:SecureTransport` Deny; force a mode via `s3:x-amz-server-side-encryption` Deny.

### CORS

Browser cross-origin — configure on **bucket** not app.
```json
[{"AllowedOrigins":["https://www.example.com"],"AllowedMethods":["GET","PUT"],
  "AllowedHeaders":["*"],"ExposeHeaders":["ETag"],"MaxAgeSeconds":3000}]
```
Preflight `OPTIONS` first. `AllowedOrigins` must match scheme+host+port exactly; `ExposeHeaders` needed for JS to read `ETag`. Presigned browser uploads need a `PUT` CORS rule.

### MFA Delete

MFA to permanently delete a version or suspend versioning. Needs versioning; enabled only by **root via CLI/API**. Protects the two destructive ops. Most orgs use Object Lock instead (no root creds needed).

### Access Logs

Server access logging → **separate** target bucket. **⚠ Never log to the bucket being logged** = infinite logging loop + surprise bill. Best-effort/delayed. **Access logs vs CloudTrail data events:** logs = free-ish/delayed/best-effort (traffic analysis); data events = near-real-time/guaranteed/IAM identity (for "who deleted this object?" and security).

### Pre-Signed URLs

Time-limited URL carrying the **generator's permissions** — anonymous holder GET/PUT one object.
```csharp
var req = new GetPreSignedUrlRequest{ BucketName="my-bucket", Key="private/report.pdf",
  Expires=DateTime.UtcNow.AddMinutes(15), Verb=HttpVerb.GET };  // PUT for browser upload
string url = s3Client.GetPreSignedURL(req);
```
Up to 7 days with IAM user long-term key. **❗ If generated with temporary role creds (Lambda/ECS/EC2), URL dies when creds expire (~1h) regardless of requested expiry** — #1 serverless presigned-URL bug. Inherits generator's perms (least-privilege role); treat as bearer token. Use for private downloads without proxying + **direct browser upload** (don't stream through your compute).

### S3 Security Best Practices + DR

Account BPA + disable ACLs · enforce encryption+TLS via Deny · SSE-KMS + Bucket Keys · versioning + Object Lock Compliance for backups · short-lived presigned from least-priv role · CloudTrail data events + logs to separate bucket · **free S3 gateway endpoint** for private subnets · Access Points for multi-team · Access Analyzer + Macie + Config.
**DR:** at risk = objects (delete/overwrite/ransomware) + config. Backup = versioning (undelete via deleting the delete-marker), MFA Delete, **Object Lock (real ransomware control)**, CRR/SRR + Batch Replication for pre-existing, lifecycle→Glacier. RPO CRR sec–min (RTC 15-min SLA); Deep Archive restore **12h** (never on critical RTO path). **❗ CRR only replicates objects created after enabling** (backfill = Batch Replication) · replication doesn't replicate deletes by default · versioning alone doesn't stop credential-compromise mass-delete (needs Object Lock/MFA Delete).
