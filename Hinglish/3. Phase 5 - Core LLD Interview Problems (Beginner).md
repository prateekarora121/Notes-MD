Tension mat lo — hum bilkul basic se advanced tak jayenge, real-life analogies ke saath.

## How to Approach ANY LLD Problem

Interviewer ko sirf final "answer" nahi chahiye — unhe dekhna hai ki aap *soch kaise rahe ho* (structured thought process). Neeche diye 6 steps har baar follow karo. Ye ek scary open-ended sawaal ko ek simple checklist bana dete hain.

### Step 1 — Requirements & Scope clarify karo
Turant code likhna shuru mat karo — pehle clarifying sawaal poocho! Scope define karo: kya banana hai (*functional* requirements) aur kaise chalna chahiye (*non-functional* — thread-safe? kitna scale? latency? extensibility?). Jo cheez aap nahi kar rahe, wo bhi bol do ("main assume kar raha hoon single machine, in-memory, no persistence jab tak aap na kaho"). Isse aap smart aur organized lagte ho.

### Step 2 — Entities / Classes pehchano (the "nouns")
Problem statement padho aur usme se **nouns** (cheezein) nikaalo — yahi aam taur pe aapki classes/interfaces ban jaati hain. Logger → `Logger`, `LogLevel`, `ILogAppender`, `ILogFormatter`. Har class ka ek hi *clear kaam* hona chahiye (Single Responsibility).

### Step 3 — Relationships define karo
Classes aapas mein kaise judi hain? Sahi relationship chuno:
- **Composition ("has-a", strong ownership)** — ek `Directory` apni files ko *own* karti hai. Directory delete → files bhi gayi.
- **Aggregation ("has-a", weak)** — ek `Logger` appenders ko *use* karta hai jo alag se bhi zinda reh sakte hain.
- **Inheritance / Realization ("is-a")** — `ConsoleAppender` *is-an* `ILogAppender`.

Rule of thumb: **inheritance se bacho, composition prefer karo** ("favour composition over inheritance").

### Step 4 — SOLID + Design Patterns lagao
Ab design ko shape do. Sawaal poocho: "kaunsa part badalta rehta hai?" — wahi jagah (seam) pattern lagane ki hai. Formatting badalti hai → **Strategy**. Object banana complex hai → **Factory**. State ke saath behaviour badalta hai → **State**. Ek hi shared instance → **Singleton**.

### Step 5 — Edge Cases & Concurrency handle karo
`null`/empty input, invalid operations, resource cleanup bolo — aur SDE-2 ke liye sabse important, **thread-safety**. Kya multiple threads isko call karenge? Shared mutable state kya hai? Usko kaise protect karoge (`lock`, concurrent collections, immutability)? Ye bolne se aap senior lagte ho.

### Step 6 — Code Walk-Through karo
Ek real scenario ko poora chalaake dikhao (jaise "user paise daalta hai → item choose karta hai → machine deti hai"). Isse prove hota hai ki design sach mein *kaam karta hai* aur koi gap toh nahi.

> **Sunehra niyam:** Bol-bol ke socho, boxes aur arrows banao, aur *extension ke liye seams chhod do*. Achha LLD answer wo hai jo kal aasani se change ho sake.

## Quick Refresher: SOLID + Common Patterns

| SOLID | Matlab (ek line) |
|-------|------------------|
| **S**ingle Responsibility | Ek class ka ek hi kaam, badalne ki ek hi wajah |
| **O**pen/Closed | Naya feature add karo bina purana chhede |
| **L**iskov Substitution | Child class parent ki jagah safely chale |
| **I**nterface Segregation | Chhote focused interfaces, ek mota nahi |
| **D**ependency Inversion | Interface pe depend karo, concrete class pe nahi |

| Pattern | Kab use karo… | Interview keyword |
|---------|---------------|-------------------|
| **Strategy** | Koi algorithm/behaviour pluggable ho | "formatter / pricing / sort varies" |
| **Factory** | Object creation logic ek jagah centralise ho | "create appropriate object" |
| **Singleton** | Bilkul ek hi shared instance chahiye | "global logger / config" |
| **Observer** | Bahut saare listeners ek event pe react karein | "notify subscribers" |
| **State** | Behaviour internal state pe depend kare | "machine in different modes" |
| **Composite** | Part-whole objects ka tree, sabko ek jaisa treat karo | "file & folder same interface" |
| **Chain of Responsibility** | Ek request handlers ki chain se guzre | "filtering pipeline" |

## Problem 1 — Design a Logger

Ye ek logging library hai — jaise log4net / NLog / Serilog. Isme **Strategy**, **Singleton**, **Observer/Appenders**, filtering aur **thread-safety** sab test hote hain, kyunki logger ko ek saath bahut saare threads call karte hain.

Real .NET projects mein aap almost hamesha `Microsoft.Extensions.Logging` (`ILogger`/`ILogger<T>`) ya **Serilog** use karoge, khud se banane ki zaroorat nahi. Par interviewer chahta hai ki aap ise *scratch se design* karo — toh neeche hum wahi karenge. Aur maze ki baat: ye scratch wala design bilkul waise hi bana hai jaise wo real libraries banti hain (sinks, formatters, level filtering, async).

### Problem Statement & Clarifying Questions

Ek aisa logging framework design karo jo messages ko alag-alag severity levels pe, multiple destinations tak, configurable formatting ke saath likh sake.

**Interviewer se poocho:**
- Kaunse **log levels**? (Assume Debug < Info < Warn < Error.)
- Kahan likhna hai (**destinations/sinks**)? (Console, file — baad mein network/DB tak extensible.)
- **Async** logging chahiye (caller thread block na ho)?
- Ek hi global **singleton** logger, ya naam se multiple named loggers (jaise `ILogger<T>`)?
- Koi **format** requirement (timestamp, thread name, JSON)?
- Kitna **throughput** aur **thread-safety** chahiye?

### Requirements

**Functional**
- Kisi level pe message log karna: `Debug/Info/Warn/Error`.
- **Level filtering** — threshold Warn hai toh Debug/Info drop karo.
- Multiple **appenders/sinks** (console, file) — ek message kai jagah fan out ho sake.
- Pluggable **formatter** (plain text, JSON, waghera).

**Non-functional**
- **Thread-safe** writing (lines aapas mein mix hokar garbage na banein).
- High throughput ke liye optional **async** mode.
- **Extensible** — naya appender/formatter add karo bina core ko chhede (Open/Closed).
- Clean **shutdown** (buffers flush, files close).

### Core Entities / Classes

| Class / Interface | Kaam | Relationship |
|-------------------|------|--------------|
| `LogLevel` (enum) | Ordered severity levels | har jagah use |
| `LogMessage` | Immutable value object (level, text, timestamp, thread) | har log call pe banta hai |
| `ILogFormatter` (interface) | `LogMessage` ko `string` mein badalna | **Strategy** |
| `ILogAppender` (interface) | Formatted line ko destination pe likhna | **Observer**-jaisa sink |
| `ConsoleAppender`, `FileAppender` | Concrete sinks | *is-a* `ILogAppender` |
| `Logger` | Facade: level se filter, appenders pe fan out | *has-a* many appenders (composition) |
| `AsyncAppender` | Decorator/wrapper jo buffer karke worker task pe likhta hai | ek `ILogAppender` ko wrap karta hai |

### Design Patterns Used

- **Strategy** → `ILogFormatter`. Formatting *badalti* hai; plain-text ↔ JSON swap karo bina appenders chhede.
- **Singleton** → root `Logger` aksar ek hi shared instance hota hai (global access, ek config). C# mein `Lazy<T>` use karo — by default thread-safe.
- **Observer / Appender list** → `Logger` har registered appender ko notify karta hai (ek event pe kai sinks react karte hain).
- **Level filter** → threshold se neeche wale messages sinks tak pahunchne se pehle hi drop.
- **Decorator** → `AsyncAppender` kisi bhi appender ko wrap karke usse transparently async bana deta hai.

### Class Design + Key Code

**Text UML-ish view:**

```
LogLevel (enum: Debug, Info, Warn, Error)

LogMessage { Level, Message, Timestamp, ThreadName }   // immutable

interface ILogFormatter { string Format(LogMessage m); }
    └── SimpleTextFormatter
    └── JsonFormatter

interface ILogAppender { void Append(LogMessage m); void Close(); }
    └── ConsoleAppender   (has-a ILogFormatter)
    └── FileAppender      (has-a ILogFormatter, has-a StreamWriter)
    └── AsyncAppender     (wraps an ILogAppender + channel + worker task)

Logger (SINGLETON)
   - LogLevel Threshold
   - appenders
   + Debug/Info/Warn/Error(string)
   + Log(level, msg)  -> filter -> fan out to appenders
```

```csharp
using System;
using System.Collections.Concurrent;
using System.IO;
using System.Threading;
using System.Threading.Channels;
using System.Threading.Tasks;

namespace LoggerDesign;

// 1) Ordered severity levels. C# enums integer-backed hote hain, toh `level >= threshold` seedha chalta hai.
public enum LogLevel { Debug, Info, Warn, Error }

// 2) Immutable value object — threads ke beech safely share ho sakta hai.
public sealed class LogMessage
{
    public LogLevel Level { get; }
    public string Message { get; }
    public long Timestamp { get; }
    public string ThreadName { get; }

    public LogMessage(LogLevel level, string message)
    {
        Level = level;
        Message = message ?? "";                     // null text pe kabhi crash na ho
        Timestamp = DateTimeOffset.UtcNow.ToUnixTimeMilliseconds();
        ThreadName = Thread.CurrentThread.Name
                     ?? $"T{Environment.CurrentManagedThreadId}";
    }
}

// 3) STRATEGY: formatting destination se independent badalti hai.
public interface ILogFormatter
{
    string Format(LogMessage m);
}

public class SimpleTextFormatter : ILogFormatter
{
    public string Format(LogMessage m) =>
        $"{m.Timestamp} [{m.ThreadName}] {m.Level} - {m.Message}";
}

public class JsonFormatter : ILogFormatter
{
    public string Format(LogMessage m) =>
        $"{{\"ts\":{m.Timestamp},\"thread\":\"{m.ThreadName}\"," +
        $"\"level\":\"{m.Level}\",\"msg\":\"{m.Message}\"}}";
}

// 4) APPENDER (sink). Har concrete appender apna formatter own karta hai (composition).
public interface ILogAppender
{
    void Append(LogMessage m);
    void Close();
}

public class ConsoleAppender : ILogAppender
{
    private readonly ILogFormatter _formatter;
    // Lock taaki do threads kabhi ek WriteLine ko interleave na karein.
    private readonly object _lock = new object();

    public ConsoleAppender(ILogFormatter formatter) => _formatter = formatter;

    public void Append(LogMessage m)
    {
        string line = _formatter.Format(m);
        lock (_lock) { Console.WriteLine(line); }
    }

    public void Close() { /* console mein close karne ko kuch nahi */ }
}

public class FileAppender : ILogAppender
{
    private readonly ILogFormatter _formatter;
    private readonly StreamWriter _writer;
    private readonly object _lock = new object();

    public FileAppender(ILogFormatter formatter, string path)
    {
        _formatter = formatter;
        _writer = new StreamWriter(path, append: true) { AutoFlush = false };
    }

    public void Append(LogMessage m)
    {
        string line = _formatter.Format(m);
        lock (_lock)                                 // ek hi writer, usko guard karo
        {
            try
            {
                _writer.WriteLine(line);
                _writer.Flush();                     // flush taaki crash pe kuch loss na ho
            }
            catch (IOException e)
            {
                // Logging kabhi app ko crash na karaye — gracefully degrade karo.
                Console.Error.WriteLine("FileAppender failed: " + e.Message);
            }
        }
    }

    public void Close()
    {
        lock (_lock)
        {
            try { _writer.Dispose(); } catch (IOException) { /* ignore */ }
        }
    }
}

// 5) DECORATOR: KISI bhi appender ko async bana do bina usko badle.
//    System.Threading.Channels .NET mein idiomatic bounded queue hai.
public class AsyncAppender : ILogAppender
{
    private readonly ILogAppender _inner;
    private readonly Channel<LogMessage> _channel =
        Channel.CreateBounded<LogMessage>(new BoundedChannelOptions(10_000)
        {
            FullMode = BoundedChannelFullMode.DropWrite  // full ho toh drop, caller kabhi na ruke
        });
    private readonly Task _worker;

    public AsyncAppender(ILogAppender inner)
    {
        _inner = inner;
        _worker = Task.Run(DrainAsync);
    }

    private async Task DrainAsync()
    {
        await foreach (var m in _channel.Reader.ReadAllAsync())
            _inner.Append(m);
    }

    public void Append(LogMessage m)
    {
        // TryWrite = non-blocking; buffer full hone pe false (DropWrite policy).
        if (!_channel.Writer.TryWrite(m))
            Console.Error.WriteLine("Log buffer full, dropping message");
    }

    public void Close()
    {
        _channel.Writer.Complete();                  // ab koi write nahi
        _worker.Wait(2000);                          // worker ko drain hone do
        _inner.Close();
    }
}

// 6) LOGGER: SINGLETON (Lazy<T> se) + level filter + fan-out (observer-jaisa).
public sealed class Logger
{
    // Lazy<T> ek thread-safe, lazily-created singleton deta hai — sabse clean C# idiom.
    private static readonly Lazy<Logger> _instance = new(() => new Logger());
    public static Logger Instance => _instance.Value;

    private volatile LogLevel _threshold = LogLevel.Info;   // change sabko turant dikhe
    private readonly ConcurrentBag<ILogAppender> _appenders = new();

    private Logger() { }

    public void SetThreshold(LogLevel level) => _threshold = level;
    public void AddAppender(ILogAppender a) => _appenders.Add(a);

    public void Log(LogLevel level, string message)
    {
        if (level < _threshold) return;              // LEVEL FILTER
        var m = new LogMessage(level, message);
        foreach (var a in _appenders) a.Append(m);   // FAN OUT
    }

    public void Debug(string msg) => Log(LogLevel.Debug, msg);
    public void Info(string msg)  => Log(LogLevel.Info,  msg);
    public void Warn(string msg)  => Log(LogLevel.Warn,  msg);
    public void Error(string msg) => Log(LogLevel.Error, msg);

    public void Shutdown()
    {
        foreach (var a in _appenders) a.Close();
    }
}
```

**Usage:**
```csharp
Logger log = Logger.Instance;
log.SetThreshold(LogLevel.Debug);
log.AddAppender(new ConsoleAppender(new SimpleTextFormatter()));
log.AddAppender(new AsyncAppender(new FileAppender(new JsonFormatter(), "app.log")));

log.Info("Server started");
log.Debug("Cache warmed");
log.Error("DB connection lost");
log.Shutdown();
```

### Thread-Safety Considerations

- **Shared appender list** → `ConcurrentBag<ILogAppender>` se bahut threads log kar sakte hain jabki beech-beech mein appender add hota rahe, bina exception. (Agar fan-out ka order maayne rakhta hai toh plain `List<T>` ko `lock` se guard karo.)
- **Singleton creation** → `Lazy<T>` by default thread-safe hai (`ExecutionAndPublication`) — haath se double-checked locking likhne ki zaroorat nahi.
- **Har sink apna write guard karta hai** → console/file writer pe `lock` taaki lines mix na ho.
- **`_threshold` `volatile` hai** → config change sabhi threads ko turant dikhta hai.
- **Async mode** → ek bounded `Channel<T>` kaam ek worker `Task` ko sौंप deta hai; underlying writer sirf ek thread chhuता hai, toh na interleaving na caller block.

### Edge Cases
- Exception/stack trace log karna (ek `Exception` overload accept karo).
- File appender: disk full, permission denied, size/date pe file rotation.
- Async queue full → drop vs block policy (`BoundedChannelFullMode` — kaun sa chuna, bolo).
- Bahut high log volume → level filtering + async slowdown rok deta hai.
- `Shutdown()` buffered/async messages flush kare (koi log na khoye).
- Formatter `null` message text safely handle kare (`LogMessage` mein handle ho gaya).

### How to Extend / Follow-ups
- **Named/hierarchical loggers** (`App.Service`) with per-namespace levels, jaise `ILogger<T>`.
- Naye appenders: **network/syslog**, **DB**, **rolling file**.
- **Scopes / correlation context** (per operation request id via `AsyncLocal<T>`).
- Async appender mein **batching** throughput ke liye; back-pressure policy.
- Structured logging / correlation ids for distributed tracing.

## Problem 2 — Design a File System (Composite)

Ye ek simple **in-memory** file system hai. Yahi **Composite pattern** ka classic sawaal hai: file aur directory dono ko ek jaisa "node" maana jaata hai ek tree mein.

### Problem Statement & Clarifying Questions

Ek in-memory file system design karo jo create, delete, `Ls`, `Find`, path resolution, aur size calculation support kare.

**Poocho:**
- Sirf in-memory, ya persistence? (Assume **in-memory**.)
- File mein **content** hoga, ya bas metadata + size? (Assume chhota content memory mein.)
- Paths **absolute** honge (`/a/b/c`)? `.`/`..` support? (Absolute rakho, `/`-separated.)
- **Permissions / symlinks**? (Beginner tier ke liye out of scope — extension ke roop mein bol do.)
- **Thread-safe**? (Haan — multiple users tree ko chhu sakte hain.)
- `Find` naam se match kare, glob se, ya predicate se? (Exact name / substring se shuru karo.)

### Requirements

**Functional**
- Path pe file/directory create karo (intermediate dirs auto-create optional).
- Ek node delete karo (directory ke liye recursive).
- `Ls(path)` — immediate children list karo.
- `Find(root, name)` — subtree mein matching names dhoondo.
- **Path resolution** — `/a/b/c` navigate karke node tak pahuncho.
- **Size** — file ka apna size; directory = saare descendants ka sum (recursive).

**Non-functional**
- **Extensible** node types (file, dir, baad mein symlink).
- **Thread-safe** mutations.
- File aur directory ko ek jaisa treat karna (**Composite**).

### Core Entities / Classes

> **Naming note:** C# mein `File` aur `Directory` pehle se `System.IO` mein hain. Confusion se bachne ke liye hum tree nodes ko `FileNode` aur `DirectoryNode` naam denge.

| Class | Kaam | Relationship |
|-------|------|--------------|
| `FileSystemNode` (abstract) | Common node: `Name`, `GetSize()`, `Print()` | tree ka base |
| `FileNode` | Leaf node; content rakhta hai; size = content length | *is-a* node (leaf) |
| `DirectoryNode` | Composite node; children dictionary ko **own** karta hai | *is-a* node; children ka **composition** |
| `FileSystem` | Facade: root + operations (create/delete/ls/find/resolve) | *has-a* root `DirectoryNode` |

> **Composite ka dil yahi hai:** `DirectoryNode` khud bhi ek `FileSystemNode` hai, aur uske andar aur `FileSystemNode` (file ya directory) hote hain. Isi recursion se tree banta hai — ek folder files *aur* folders dono rakh sakta hai, hamesha ke liye.

### Design Patterns Used

- **Composite** → `FileNode` (leaf) aur `DirectoryNode` (composite) dono `FileSystemNode` base type share karte hain, toh client code dono ko ek jaisa treat karta hai (`node.GetSize()` dono pe chalta hai).
- **(Optional) Iterator / Visitor** → `Find` ya total size jaise traversals ke liye Visitor formalise kar sakte ho; beginner tier ke liye simple recursive method kaafi hai.

### Class Design + Key Code

**Text UML-ish view:**

```
abstract FileSystemNode { Name; GetSize(); Print(indent); }
        ├── FileNode       (content; size = content.Length)   [LEAF]
        └── DirectoryNode  (Dictionary<string, FileSystemNode> children)  [COMPOSITE]
                            + Add(node) / Remove(name) / GetChild(name)
                            + GetSize() = sum of children.GetSize()

FileSystem { DirectoryNode root ("/") ; Mkdir/CreateFile/Delete/Ls/Find/Resolve }
```

```csharp
using System;
using System.Collections.Generic;

namespace FileSystemDesign;

// COMPOSITE base — files AND directories dono ka common type.
public abstract class FileSystemNode
{
    public string Name { get; }
    protected FileSystemNode(string name) => Name = name;

    public abstract long GetSize();               // leaf & composite dono jawab dete hain
    public abstract void Print(string indent);    // pretty tree print
}

// LEAF
public class FileNode : FileSystemNode
{
    private string _content;

    public FileNode(string name, string content) : base(name)
        => _content = content ?? "";

    public void Write(string content) => _content = content ?? "";
    public string Read() => _content;

    public override long GetSize() => _content.Length;

    public override void Print(string indent)
        => Console.WriteLine($"{indent}- {Name} ({GetSize()}b)");
}

// COMPOSITE
public class DirectoryNode : FileSystemNode
{
    // Modern .NET mein Dictionary insertion order preserve karta hai — stable Ls ke liye.
    private readonly Dictionary<string, FileSystemNode> _children = new();
    private readonly object _lock = new object();

    public DirectoryNode(string name) : base(name) { }

    public void Add(FileSystemNode node)
    {
        lock (_lock)
        {
            if (_children.ContainsKey(node.Name))
                throw new ArgumentException("Already exists: " + node.Name);
            _children[node.Name] = node;
        }
    }

    public void Remove(string childName)
    {
        lock (_lock)
        {
            if (!_children.Remove(childName))
                throw new KeyNotFoundException("Not found: " + childName);
        }
    }

    public FileSystemNode? GetChild(string childName)
    {
        lock (_lock)
        {
            return _children.TryGetValue(childName, out var n) ? n : null;
        }
    }

    public List<FileSystemNode> List()
    {
        lock (_lock)
        {
            return new List<FileSystemNode>(_children.Values);  // copy = iterate karna safe
        }
    }

    // Directory size = saare descendants ka recursive sum. Composite in action.
    public override long GetSize()
    {
        lock (_lock)
        {
            long total = 0;
            foreach (var child in _children.Values) total += child.GetSize();
            return total;
        }
    }

    public override void Print(string indent)
    {
        Console.WriteLine($"{indent}+ {Name}/");
        foreach (var child in List()) child.Print(indent + "  ");
    }
}

// FACADE with path operations.
public class FileSystem
{
    private readonly DirectoryNode _root = new DirectoryNode("");   // "" matlab "/"

    // "/a/b/c" ko split karo -> ["a","b","c"]
    private string[] Parts(string path)
    {
        if (path == null || !path.StartsWith("/"))
            throw new ArgumentException("Path must be absolute: " + path);
        string trimmed = path == "/" ? "" : path.Substring(1);
        return trimmed.Length == 0 ? Array.Empty<string>() : trimmed.Split('/');
    }

    // PATH RESOLUTION: root se 'path' wale node tak chalो.
    public FileSystemNode Resolve(string path)
    {
        FileSystemNode current = _root;
        foreach (var p in Parts(path))
        {
            if (current is not DirectoryNode dir)
                throw new ArgumentException("Not a directory in path: " + path);
            current = dir.GetChild(p)
                      ?? throw new KeyNotFoundException("No such path: " + path);
        }
        return current;
    }

    private DirectoryNode ResolveParentDir(string path)
    {
        var p = Parts(path);
        FileSystemNode current = _root;
        for (int i = 0; i < p.Length - 1; i++)          // last segment se pehle ruk jao
        {
            if (current is not DirectoryNode dir)
                throw new ArgumentException("Bad parent path: " + path);
            current = dir.GetChild(p[i])
                      ?? throw new KeyNotFoundException("Bad parent path: " + path);
        }
        return (DirectoryNode)current;
    }

    public void Mkdir(string path)
    {
        var p = Parts(path);
        ResolveParentDir(path).Add(new DirectoryNode(p[^1]));
    }

    public void CreateFile(string path, string content)
    {
        var p = Parts(path);
        ResolveParentDir(path).Add(new FileNode(p[^1], content));
    }

    public void Delete(string path)
    {
        var p = Parts(path);
        ResolveParentDir(path).Remove(p[^1]);   // dir hataoge toh uska poora subtree gaya
    }

    // Ls: immediate children ke naam.
    public List<string> Ls(string path)
    {
        var node = Resolve(path);
        if (node is FileNode) return new List<string> { node.Name };
        var names = new List<string>();
        foreach (var c in ((DirectoryNode)node).List()) names.Add(c.Name);
        return names;
    }

    // Find: subtree ka recursive search exact name match ke liye; node refs return karta hai.
    public List<FileSystemNode> Find(string startPath, string targetName)
    {
        var results = new List<FileSystemNode>();
        Dfs(Resolve(startPath), targetName, results);
        return results;
    }

    private void Dfs(FileSystemNode node, string target, List<FileSystemNode> outList)
    {
        if (node.Name == target) outList.Add(node);
        if (node is DirectoryNode dir)
            foreach (var c in dir.List()) Dfs(c, target, outList);
    }

    public long Size(string path) => Resolve(path).GetSize();
    public void PrintTree() => _root.Print("");
}
```

**Usage:**
```csharp
var fs = new FileSystem();
fs.Mkdir("/home");
fs.Mkdir("/home/parteek");
fs.CreateFile("/home/parteek/notes.txt", "hello LLD");
fs.CreateFile("/home/parteek/todo.txt", "learn composite");

Console.WriteLine(string.Join(", ", fs.Ls("/home/parteek")));  // notes.txt, todo.txt
Console.WriteLine(fs.Size("/home"));                            // 9 + 15 = 24
fs.Find("/", "notes.txt");                                      // -> the FileNode
fs.Delete("/home/parteek/todo.txt");
fs.PrintTree();
```

### Thread-Safety Considerations
- Har `DirectoryNode` apni mutations (`Add/Remove/List/GetSize`) ko `lock` se guard karta hai — children dictionary hi shared mutable state hai.
- `List()` ek **copy** deta hai, toh callers bina lock pakde iterate kar sakte hain ("collection modified" exception se bacho).
- Zyada concurrency chahiye toh `Dictionary` + `lock` ko `ConcurrentDictionary` se badlo, ya `ReaderWriterLockSlim` use karo (`Ls`/`Find` ke liye bahut readers, `Create`/`Delete` ke liye exclusive writers).
- **Deadlock** se savdhaan agar kabhi ek saath do directories lock karo (jaise `Move`) — hamesha ek fixed order mein lock karo (jaise path se).

### Edge Cases
- Aise node ka creation jiska parent hi na ho → error do ya intermediate dirs auto-create karo (apna choice batao).
- Ek hi directory mein duplicate naam.
- Root `/` ya na-maujood path delete karna.
- Trailing slash wala path, empty path, ya relative path (reject karo ya normalise).
- Ek `FileNode` ko `DirectoryNode` samajh lena (file pe `Ls`).
- Bade/deep trees → recursion depth (bahut deep trees ke liye iterative traversal mention karo).

### How to Extend / Follow-ups
- `.` aur `..`, relative paths, current-working-directory support.
- **Symlinks** (ek node doosre path ko point kare — `GetSize`/`Find` mein cycles se savdhaan).
- Permissions/ownership, timestamps (created/modified).
- `Move`/`Copy`, `Find` mein glob/regex, directory size caching.
- Persistence (tree serialize), quotas.

## Problem 3 — Design a Vending Machine (State)

Ye **State pattern** ka textbook sawaal hai. Machine apne current mode ke hisaab se alag behave karti hai — *Idle*, *HasMoney*, *Dispensing*, *OutOfStock*. Same button dabao, par result state ke hisaab se badalta hai.

### Problem Statement & Clarifying Questions

Ek vending machine design karo jo inventory ke saath items rakhe, coins/notes accept kare, user ko product select karne de, dispense kare, aur change wapas de.

**Poocho:**
- Payment: sirf **coins/notes**, ya card bhi? (Abhi ke liye coins/notes assume.)
- Beech transaction mein user **cancel** karke refund le sakta hai? (Haan.)
- **Exact change** chahiye, ya machine khud change banati hai? (Machine change banati hai agar kar sake.)
- Ek transaction mein ek item ya multiple? (Ek assume karo.)
- **Thread-safety** — ek physical machine, ek time ek user, par admin refill saath mein? (Inventory guard karo.)
- **Out of stock** ya **insufficient money** pe kya hoga?

### Requirements

**Functional**
- Paise daalo (balance accumulate karo).
- Product select karo (code se, jaise `A1`).
- Balance ≥ price aur item in-stock ho toh dispense karo.
- **Change** wapas do (balance − price).
- **Cancel** → daale hue paise refund.
- Admin: inventory refill, coins restock.

**Non-functional**
- Clean **State pattern** — har state decide kare ki har action kya karega.
- **Thread-safe** inventory/coin updates.
- Extensible states & payment methods.

### Core Entities / Classes

| Class / Interface | Kaam | Relationship |
|-------------------|------|--------------|
| `Item` | Product: name, price, code | value object |
| `Inventory` | Har item ka stock count; check/deduct/refill | *has-a* items |
| `Coin` (enum) | Denominations (5, 10, 20, 50, 100) | value |
| `IVendingMachineState` (interface) | Actions define kare: `InsertMoney`, `SelectItem`, `Dispense`, `Cancel` | **State** |
| `IdleState`, `HasMoneyState`, `DispensingState`, `OutOfStockState` | Concrete behaviours | *is-a* state |
| `VendingMachine` (context) | Current state, balance, inventory rakhta hai; actions state ko delegate karta hai | *has-a* one state |

> **Relationship:** `VendingMachine` (context) ke paas ek current `IVendingMachineState` hai; states wapas machine mein call karke balance change karte hain, stock deduct karte hain, aur agle state mein **transition** karte hain.

### Design Patterns Used

- **State** → design ka dil. Har action (`InsertMoney`, `SelectItem`, `Dispense`, `Cancel`) har state ke andar alag likha hai; machine current state ko kaam saंpती hai aur state hi transitions drive karti hai. Isse woh bada `if/else`/`switch` (status flag pe) hat jaata hai.
- **(Optional) Strategy** → pluggable **payment** (coins vs card) ya **pricing**.
- **(Optional) Singleton** → ek physical machine instance.
- **(Optional) Factory** → sahi state object banane ke liye.

### Class Design + Key Code

**Text UML-ish view:**

```
Item { Code, Name, Price }
enum Coin { Five=5, Ten=10, Twenty=20, Fifty=50, Hundred=100 }
Inventory { Dictionary<code, Item>, Dictionary<code, count>  + HasStock/Deduct/Refill }

interface IVendingMachineState {
    void InsertMoney(int amount);
    void SelectItem(string code);
    void Dispense();
    void Cancel();
}
   ├── IdleState        (waiting; sirf InsertMoney kuch karta hai)
   ├── HasMoneyState    (money in; SelectItem price/stock check karta hai)
   ├── DispensingState  (item + change release, phir -> Idle)
   └── OutOfStockState  (item unavailable; refund, wapas Idle)

VendingMachine (CONTEXT)
   - state, balance, selectedCode, Inventory
   + SetState(), AddBalance(), Refund(), transitions
   + public: InsertMoney/SelectItem/Dispense/Cancel  -> delegate to state
```

```csharp
using System;
using System.Collections.Generic;

namespace VendingMachineDesign;

public class Item
{
    public string Code { get; }
    public string Name { get; }
    public int Price { get; }

    public Item(string code, string name, int price)
    {
        Code = code; Name = name; Price = price;
    }
}

// C# enums Java ki tarah constructor nahi rakh sakte, par hum underlying integer
// ko HI denomination bana sakte hain: (int)Coin.Ten == 10.
public enum Coin { Five = 5, Ten = 10, Twenty = 20, Fifty = 50, Hundred = 100 }

public class Inventory
{
    private readonly Dictionary<string, Item> _items = new();
    private readonly Dictionary<string, int> _counts = new();
    private readonly object _lock = new object();

    public void AddItem(Item item, int count)
    {
        lock (_lock)
        {
            _items[item.Code] = item;
            _counts[item.Code] = _counts.GetValueOrDefault(item.Code) + count;
        }
    }

    public Item? GetItem(string code)
    {
        lock (_lock) { return _items.GetValueOrDefault(code); }
    }

    public bool HasStock(string code)
    {
        lock (_lock) { return _counts.GetValueOrDefault(code) > 0; }
    }

    public void Deduct(string code)
    {
        lock (_lock)
        {
            int c = _counts.GetValueOrDefault(code);
            if (c <= 0) throw new InvalidOperationException("Out of stock: " + code);
            _counts[code] = c - 1;
        }
    }
}

// STATE interface: har action per-state define hota hai.
public interface IVendingMachineState
{
    void InsertMoney(int amount);
    void SelectItem(string code);
    void Dispense();
    void Cancel();
}

// CONTEXT
public class VendingMachine
{
    private IVendingMachineState _state;
    private readonly Inventory _inventory;
    private readonly object _gate = new object();   // lock same thread pe reentrant hota hai
    private int _balance = 0;
    private string? _selectedCode = null;

    public VendingMachine(Inventory inventory)
    {
        _inventory = inventory;
        _state = new IdleState(this);   // Idle se shuru
    }

    // --- state management + helpers jo states use karte hain ---
    internal void SetState(IVendingMachineState s) => _state = s;
    internal Inventory Inventory => _inventory;
    internal int Balance => _balance;
    internal void AddBalance(int amt) => _balance += amt;
    internal void ResetBalance() => _balance = 0;
    internal void SetSelectedCode(string? c) => _selectedCode = c;
    internal string? SelectedCode => _selectedCode;

    internal void Refund()
    {
        if (_balance > 0) Console.WriteLine("Refunding " + _balance);
        ResetBalance();
        _selectedCode = null;
    }

    // --- public API CURRENT state ko delegate karta hai ---
    public void InsertMoney(int amount) { lock (_gate) { _state.InsertMoney(amount); } }
    public void SelectItem(string code) { lock (_gate) { _state.SelectItem(code); } }
    public void Dispense()              { lock (_gate) { _state.Dispense(); } }
    public void Cancel()                { lock (_gate) { _state.Cancel(); } }
}

// IDLE: paiso ka intezaar.
public class IdleState : IVendingMachineState
{
    private readonly VendingMachine _m;
    public IdleState(VendingMachine m) => _m = m;

    public void InsertMoney(int amount)
    {
        _m.AddBalance(amount);
        Console.WriteLine("Balance: " + _m.Balance);
        _m.SetState(new HasMoneyState(_m));           // transition
    }
    public void SelectItem(string code) => Console.WriteLine("Insert money first.");
    public void Dispense() => Console.WriteLine("Insert money & select item.");
    public void Cancel() => Console.WriteLine("Nothing to cancel.");
}

// HAS MONEY: user aur daal sakta hai, select kar sakta hai, ya cancel.
public class HasMoneyState : IVendingMachineState
{
    private readonly VendingMachine _m;
    public HasMoneyState(VendingMachine m) => _m = m;

    public void InsertMoney(int amount)
    {
        _m.AddBalance(amount);
        Console.WriteLine("Balance: " + _m.Balance);
    }
    public void SelectItem(string code)
    {
        Item? item = _m.Inventory.GetItem(code);
        if (item == null) { Console.WriteLine("Invalid item: " + code); return; }
        if (!_m.Inventory.HasStock(code))
        {
            Console.WriteLine(item.Name + " is out of stock.");
            _m.SetState(new OutOfStockState(_m));
            return;
        }
        if (_m.Balance < item.Price)
        {
            Console.WriteLine($"Insufficient. Need {item.Price - _m.Balance} more.");
            return;                                  // HasMoney mein hi ruko
        }
        _m.SetSelectedCode(code);
        _m.SetState(new DispensingState(_m));        // transition
        _m.Dispense();                               // dispensing trigger karo
    }
    public void Dispense() => Console.WriteLine("Select an item first.");
    public void Cancel() { _m.Refund(); _m.SetState(new IdleState(_m)); }
}

// DISPENSING: item + change release, phir wapas Idle.
public class DispensingState : IVendingMachineState
{
    private readonly VendingMachine _m;
    public DispensingState(VendingMachine m) => _m = m;

    public void InsertMoney(int amount) => Console.WriteLine("Dispensing, please wait.");
    public void SelectItem(string code) => Console.WriteLine("Dispensing, please wait.");
    public void Cancel() => Console.WriteLine("Cannot cancel during dispensing.");

    public void Dispense()
    {
        string code = _m.SelectedCode!;
        Item item = _m.Inventory.GetItem(code)!;
        _m.Inventory.Deduct(code);                   // stock kam karo
        int change = _m.Balance - item.Price;
        Console.WriteLine("Dispensed: " + item.Name);
        if (change > 0) Console.WriteLine("Change: " + change);
        _m.ResetBalance();
        _m.SetSelectedCode(null);
        _m.SetState(new IdleState(_m));              // agle customer ke liye ready
    }
}

// OUT OF STOCK: refund karo aur reset.
public class OutOfStockState : IVendingMachineState
{
    private readonly VendingMachine _m;
    public OutOfStockState(VendingMachine m) => _m = m;

    public void InsertMoney(int amount) => Console.WriteLine("Item unavailable.");
    public void SelectItem(string code) => Console.WriteLine("Item unavailable.");
    public void Dispense() => Console.WriteLine("Item unavailable.");
    public void Cancel() { _m.Refund(); _m.SetState(new IdleState(_m)); }
}
```

**Usage (walk-through):**
```csharp
var inv = new Inventory();
inv.AddItem(new Item("A1", "Coke", 25), 2);
inv.AddItem(new Item("A2", "Water", 15), 0);   // out of stock

var vm = new VendingMachine(inv);
vm.InsertMoney(20);      // Idle -> HasMoney, balance 20
vm.InsertMoney(10);      // balance 30
vm.SelectItem("A1");     // price 25, stock ok -> Dispensing -> "Coke", change 5 -> Idle
vm.SelectItem("A2");     // ab phir paise chahiye (Idle): "Insert money first."
vm.InsertMoney(50);
vm.SelectItem("A2");     // out of stock -> OutOfStock
vm.Cancel();             // refund 50 -> Idle
```

**State transition table:**

| Current state | InsertMoney | SelectItem | Dispense | Cancel |
|---------------|-------------|------------|----------|--------|
| **Idle** | +balance → HasMoney | "insert money" | no-op | no-op |
| **HasMoney** | +balance | price/stock ok → Dispensing; warna stay/OutOfStock | "select first" | refund → Idle |
| **Dispensing** | wait | wait | release + change → Idle | can't cancel |
| **OutOfStock** | unavailable | unavailable | unavailable | refund → Idle |

Upar wali table poori kahani bata deti hai — har state mein har action ka kya hota hai aur agla state kaun sa. Interview mein ye table bana do, aadhi baat wahin clear ho jaati hai.

### Thread-Safety Considerations
- Physical machine ek time ek customer serve karti hai, par ek **admin refill** saath mein chal sakta hai → `Inventory` guard karo (saare methods `lock` mein, ya `ConcurrentDictionary`).
- Context ke public actions `lock` lete hain taaki `SelectItem` + `Dispense` sequence atomic ho aur state transitions aadhe-adhoore na dikhein. (Note: `lock`/`Monitor` same thread pe **reentrant** hai, isliye `SelectItem` ka andar hi `Dispense` call karna safe hai.)
- **Sabse important: `Deduct` stock-check ke saath atomic hona chahiye** — warna do flows dono `HasStock` pass kar ke over-dispense kar denge (check-then-act race). Check + deduct ek hi lock ke andar rakho.
- `_balance`/`_selectedCode` per-machine mutable state hain — machine ke apne lock se protected.

### Edge Cases
- Insufficient balance → aur paise maango, dispense mat karo.
- Invalid/unknown item code.
- Item bilkul us waqt out of stock ho jaye jab select kiya.
- Exact-change-only scenario (machine change nahi bana sakti) → reject karo ya exact amount maango.
- Dispensing ke beech cancel (mana karo) vs HasMoney ke beech (refund).
- Zero/negative paisa daala → reject.
- Aisa coin/note jo machine accept nahi karti.

### How to Extend / Follow-ups
- **Card/UPI payment** ek `IPaymentStrategy` se (Strategy pattern).
- Limited coin inventory ke saath change banana (greedy/DP) aur coin restocking.
- Ek transaction mein multiple items / shopping-cart mode.
- Maintenance / admin state; display panel **Observer** se.
- Sales, telemetry, price changes persist karo.
- Scale pe concurrency (bahut saari networked machines).

> Chhoti machine ke liye enum state pe ek `switch` expression bhi chalega, par jaise behaviours aur transitions badhein, **State pattern zyada scale karta hai** — interview mein isse hi prefer karo.

## Quick Revision Tips

- Har baar **6-step method** chalao: clarify → entities → relationships → SOLID/patterns → edge cases & concurrency → code walk-through.
- Pattern ka **naam bolo** aur *kyun* bolo — "formatting badalti hai, isliye main Strategy use karunga."
- **Inheritance se composition better.** Hamesha interface pe code karo.
- Bada `if/else` (status pe) ho toh **State** lagao; type pe ho toh **polymorphism/Strategy**.
- SDE-2 ke liye **thread-safety** zaroor bolo aur ek concrete tareeka batao (`lock`, concurrent collection, immutability, single-writer channel/queue).
- **Class ke boxes** aur ek **state/transition table** banao — diagram interview jitwa deta hai.
- Code **focused aur compilable-ish** rakho; important methods likho, baaki stub karke bol do ki stub kar rahe ho.

> **Antim mantra:** *Clarify karo, structure do, apne patterns ka naam lo, shared state protect karo, aur code walk karo.* Logger, File System, aur Vending Machine pe ye tab tak karo jab tak muscle memory na ban jaye — phir koi bhi LLD problem easy lagegi. All the best!
